# T04 plan: CI step for the OSINT pipeline E2E

Issue: #63. Status: plan only. Nothing in `.github/workflows/ci.yml` changes until this plan is approved.

## Dependency status

T04 depends on T02. T02 is merged (`face16d`, PR #76): `tests/e2e_pipeline/` exists on `main`, the `e2e` pytest marker is registered in `pyproject.toml`, and default `addopts = "-m 'not e2e'"` keeps the frontend job from picking the suite up. T03 (negative cases) is not required for this CI step; when those tests land they share the same marker and path and ride along for free.

## What runs today

- The `e2e` job in `.github/workflows/ci.yml` builds the Compose stack (Postgres 17 + API + Streamlit), seeds the demo data, and runs Playwright under `tests/e2e/`. Job env already sets `POSTGRES_USER/PASSWORD/DB=test` and `JWT_SECRET_KEY`, which Compose interpolates.
- The pipeline suite under `tests/e2e_pipeline/` starts its **own** uvicorn on a free localhost port against `localhost:5432`, runs `alembic upgrade head`, registers a synthetic OSINT user, resets camera 1 to Dormant, and drives `LiveOsintRunner` with fakes only (no Groq, no ntfy, no external network). It never talks to the Compose API on `:8000`.
- `scripts/check` does not run `-m e2e`. Pipeline E2E is currently a local-only check.

## Options considered

### A. Add a step to the existing `e2e` job (task preference)

Run `pytest -m e2e tests/e2e_pipeline` inside the Playwright job, after Compose is up, against the published Postgres on `:5432`.

Rejected. Sharing that database with the Compose API and the Playwright seed is not safe:

1. **Shared mutable state.** Compose `api` holds open connections and has already migrated and seeded (camera 1 Active, demo users). The pipeline fixture migrates again, registers `osint.e2e.pipeline`, and flips camera 1 to Dormant. Playwright then asserts against seed state that the pipeline just changed, or the reverse if the order is flipped. Either order can flake.
2. **Wrong process under test.** The harness deliberately starts a subprocess API so it owns lifecycle and always stops it. Pointing it at Compose's API would change the contract T02 built and still leave Compose Postgres contaminated.
3. **Heavier job for no gain.** The pipeline suite needs backend + ai-brain Python deps. The `e2e` job today is Node/Playwright + Docker. Folding pip installs into it lengthens the already 20-minute Compose path without reusing anything the suite actually needs (frontend, Playwright, seed).

### B. New job with a Postgres service (recommended)

Mirror the `backend` job: a `postgres:17-alpine` service with the same `test`/`test`/`test` credentials, install backend + ai-brain requirements, run `pytest -m e2e tests/e2e_pipeline -q`. No Compose, no Playwright, no `docker-compose.yml` edit, no new dependency.

This matches the task's "otherwise" path and is what the harness was written for (local test Postgres + subprocess API).

### C. New job that starts only Compose Postgres

Possible, but slower and still needs a `docker-compose.yml` / env dance to avoid starting `api` and `frontend`. Option B is the same isolation with less moving surface. Rejected.

## Exact YAML (option B)

Append this job to `.github/workflows/ci.yml` after the existing `e2e` job. No other job changes.

```yaml
  e2e-pipeline:
    runs-on: ubuntu-latest
    timeout-minutes: 10
    services:
      postgres:
        image: postgres:17-alpine
        env:
          POSTGRES_USER: test
          POSTGRES_PASSWORD: test
          POSTGRES_DB: test
        ports:
          - 5432:5432
        options: >-
          --health-cmd pg_isready
          --health-interval 10s
          --health-timeout 5s
          --health-retries 5
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.11"
      - name: Install pipeline E2E dependencies
        run: |
          pip install -r backend/requirements.txt
          pip install -r backend/requirements-dev.txt
          pip install -r ai-brain/requirements.txt
      - name: Run OSINT pipeline E2E
        env:
          POSTGRES_USER: test
          POSTGRES_PASSWORD: test
          POSTGRES_DB: test
          POSTGRES_HOST: localhost
          POSTGRES_PORT: "5432"
          PYTHONPATH: .
          JWT_SECRET_KEY: heimdall-ci-test-key-not-for-production-use-only
          JWT_ALGORITHM: HS256
          JWT_ACCESS_TOKEN_MINUTES: "30"
        run: pytest -m e2e tests/e2e_pipeline -q
```

### Why each piece is there

| Piece | Reason |
| --- | --- |
| Separate job name `e2e-pipeline` | Keeps Playwright failures distinct from pipeline failures in the GitHub UI. |
| Same Postgres service block as `backend` | Proven pattern; credentials match `tests/e2e_pipeline/conftest.py` `TEST_ENV` and `scripts/check`. |
| `backend/requirements.txt` + `requirements-dev.txt` | uvicorn, alembic, SQLAlchemy, psycopg2, pytest, and the API itself. `conftest._backend_python()` falls back to `sys.executable` when `.venv/backend` is absent, so the runner Python must have these packages. |
| `ai-brain/requirements.txt` | `LiveOsintRunner` and friends import `requests` / dotenv; `sys.path` already adds `ai-brain/`. |
| Env block | Identical to the backend test step plus `PYTHONPATH=.`. `ENABLE_USER_REGISTRATION` is set inside the fixture (`_api_env`), not needed at job level. |
| `pytest -m e2e tests/e2e_pipeline -q` | CLI `-m e2e` overrides `addopts = "-m 'not e2e'"` (pytest puts `addopts` first; the last `-m` wins). Path limits the run to the pipeline package so a future unrelated `e2e` mark elsewhere does not sneak in. |
| `timeout-minutes: 10` | Local runs finish in well under a minute once Postgres is healthy; 10 minutes leaves headroom without matching the Compose job's 20. |

## Why this is safe

1. **No Compose / Playwright coupling.** The Playwright `e2e` job is untouched. A red pipeline job cannot flake the browser suite, and the reverse is also true.
2. **No protected-file side effects beyond the planned `ci.yml` edit.** No `docker-compose.yml`, no Alembic, no auth, no models.
3. **No new dependency.** Install lines reuse existing requirement files. Groq / ntfy stay out of the path because the suite uses `StaticAdapter` and `ScriptedClassifier` only.
4. **Synthetic credentials only.** Username `osint.e2e.pipeline` and its password live in the test module; JWT secret matches the existing CI test key. Nothing from a real `.env` is read (the fixture forces `TEST_ENV` and `ENABLE_USER_REGISTRATION=true`).
5. **API always stopped.** `api_url` is a session fixture with `finally: _stop(process)`, so a failed assertion still terminates uvicorn and does not leak into later steps (there are none).
6. **Default local/CI deselection unchanged.** `pyproject.toml` still deselects `e2e` for `pytest tests/` in the frontend job. Only this new job opts in.
7. **T03-ready.** Negative cases will use the same marker and directory; no second CI change is required when T03 merges.
